# 칼럼 루틴 작업 설명서 (생활정보 · 업계 정보)

이 저장소의 `_column/` 은 네 사이트가 같이 쓰는 칼럼 엔진이다 — 큰길이벤트(/life/) · 이벤트 코리아 · 큰길브리지 · 진지노샵(/column/).
엔진 `scripts/column.mjs` 는 네 저장소에서 **똑같은 파일**이다. 고치면 네 곳을 같이 고친다. 사이트마다 다른 것은 `_column/config.json` 뿐이다.

## 0. 왜 이렇게 하나 — 유입 전략

1. **생활정보로 넓게 들어오게 한다.** 사람들은 "페덱스 세금계산서 메일", "택배 통관 문자 사기"처럼 *지금 겪은 일*을 검색한다. 검색량이 업계 키워드보다 훨씬 크고, 광고 경쟁이 없다.
2. **같은 이슈를 사이트마다 다른 각도로 쓴다.** 네 사이트에 같은 글을 올리면 검색엔진이 유사문서로 보고 하나만 남긴다. 그래서 같은 사건을
   - 큰길이벤트: 행사 담당자 · 총무 · 지역 주민 입장
   - 이벤트 코리아: 이벤트 회사 · 프리랜서(해외 장비 구매, 입찰 · 계약 메일) 입장
   - 큰길브리지: 소상공인 · 홈페이지 운영자(주소창 · 도메인 읽는 법, 계정 보안) 입장
   - 진지노샵: 해외직구 · 영양제 구매자(통관 · 배송 사칭) 입장
   으로 **목차부터 다르게** 쓴다. 검사기 `--also` 로 서로 30% 넘게 겹치면 막는다.
3. **글 끝에서 자연스럽게 본업으로 잇는다.** 생활정보 본문의 8할은 우리 회사 없이도 쓸모 있어야 한다. 마지막 CTA 블록(설정에 있음)과 본문 속 내부 링크 1~2개로만 잇는다. 본문 중간에 광고 문단을 넣지 않는다.
4. **업계 글은 "도시 + 업계 키워드"로 롱테일을 잡는다.** 하루 2개. 도시 이름은 제목 · 첫 문단 · 소제목 하나에만 자연스럽게. 도시 이름만 바꿔 끼운 글(도어웨이 페이지)은 구글 · 네이버 모두 벌점을 준다 — 검사기가 도시 이름 10번 초과, 기존 글과 30% 초과 겹침을 막는다.
   - 도시 글에는 그 도시에서 **확인한 사실 2가지 이상**(공식 누리집의 행사장 · 축제 · 기관 안내 등, 주소를 sources 에 단다)을 넣는다. 확인할 게 없으면 도시 없이 쓴다(city 칸을 비운다).
   - 우리가 그 도시에서 일했다, 지점이 있다 같은 말은 **사실일 때만** 쓴다. 모르면 "전국 비대면 · 전화 상담"처럼 설정 CTA 에 있는 말만 쓴다.
5. **실제 사례가 가장 강하다.** 형님이 받은 메일 · 문자 캡처가 있으면 개인정보(받는 사람 주소, 전화번호, 이름, 계좌)를 반드시 가린 뒤 `<base>img/` 에 넣고 쓴다. 가리지 않은 원본은 절대 커밋하지 않는다.

## 1. 하루 순서 (루틴)

1. 최신 main 에서 시작한다: `git pull --rebase origin main`.
2. `node scripts/column.mjs plan` — 오늘 쓸 업계 글 2개(주제 · 도시 · 핵심 키워드)와 최근 생활정보 글 목록이 나온다.
3. 글을 쓴다 → `_column/posts/<오늘>-<slug>.json` (형식 3장).
4. `node scripts/column.mjs check <새 파일들> [--also ../다른저장소/_column/posts]` 가 통과할 때까지 고친다. 세 번 고쳐도 안 되면 그 글은 버리고 보고한다. **검사를 통과시키려고 억지 문장을 끼우지 않는다.**
5. `node scripts/column.mjs build` — `<base>` 아래 글 페이지 · 목록 · rss.xml · sitemap.xml 을 만든다. robots.txt 에 칼럼 사이트맵 줄이 없으면 붙인다.
6. `git add _column <base 폴더> robots.txt` → 커밋 → `git push origin main`. 거절되면 `git pull --rebase origin main` 후 build 를 다시 돌리고 push.
7. 끝에 보고한다(5장).

오늘 날짜(한국)는 `node -e "console.log(new Date(Date.now()+9*3600e3).toISOString().slice(0,10))"` 로 구한다(루틴은 UTC 전날 밤에 돈다).

## 2. 절대 쓰지 않는 것 (공통)

- 가격 · 금액("○○원"), 회사 연혁 · 경력 연수 · 실적 건수 · 순위 · 만족도 · 후기 · 고객 발언. 검사기가 일부를 막는다.
- "100% · 무조건 · 보장 · 업계 1위 · 최초" 같은 말.
- 확인 못 한 법 조항 · 수치 · 전화번호 · 기관 절차. **출처 주소를 단 것만** 쓴다. 블로그 · 카페 · 업체 광고 글은 사실의 근거가 아니다(사례 원문으로 인용하는 것은 된다 — "이런 사례가 올라왔습니다" + 출처).
- 주소를 짐작해서 만들지 않는다. 검색 결과에 나온 주소를 그대로 복사한다.
- 다른 업체 비방 · 경쟁사 이름. 사칭당한 회사(예: FedEx)를 탓하는 말도 쓰지 않는다 — 그 회사도 피해자다.
- 사람 얼굴이 크게 나온 사진, 가리지 않은 개인정보, AI 로 만든 가짜 캡처.
- "~에 대해 알아보겠습니다" 같은 빈 도입. 첫 문장이 답이다.

## 3. 글 형식 (`_column/posts/<date>-<slug>.json`)

| 칸 | 규칙 |
|---|---|
| `slug` | 한글 · 영소문자 · 숫자 · `-`, 70자 이하 |
| `date` | 오늘(한국) `YYYY-MM-DD`. 미래 날짜는 그날까지 게시되지 않는다 |
| `category` | `life`(생활정보) · `industry`(업계 정보) — 사이트에 있는 것만 |
| `topic` | industry 는 `plan` 이 준 id 그대로. life 는 짧은 영문 id(예: `phishing-fedex-tax-invoice`) |
| `city` | 선택. 넣으면 제목 · lead 에 그 도시 이름이 있어야 한다 |
| `title` | 15~60자. 핵심 키워드를 통째로, 앞쪽에 |
| `description` | 60~170자. 검색 결과에 그대로 보인다 |
| `keyword` | `{ "main": "...", "sub": [...] }` — main 은 제목과 lead 에 통째로, 본문 12번 이하 |
| `lead` | 80~450자. 첫 문장에 결론 |
| `points` | 3~5개. 본문을 안 읽어도 답이 되는 문장 |
| `sections` | 4~8개. `{ "h2": "1. …", "blocks": [ … ] }`. 표 1개 이상 |
| `faq` | 2~6개 `{ "q", "a" }` — 구조화 데이터(FAQPage)로 나간다 |
| `sources` | `{ "name", "url" }` — life 2개 이상, industry 1개 이상, 전부 https |
| `cover` | 선택. 대표 이미지 경로(없으면 본문 첫 사진 → 사이트 기본 이미지) |
| `cta` | 선택. 없으면 config 의 카테고리 CTA |

블록: `{ "p" }` · `{ "ul": [] }` · `{ "ol": [] }` · `{ "table": { "head": [], "rows": [[]] } }` · `{ "tip" }` · `{ "warn" }` · `{ "quote": { "text", "from" } }` · `{ "img": { "src": "/column/img/x.jpg", "alt": "8자 이상", "caption", "w", "h" } }`
글 안 꾸밈은 `**굵게**` 와 `[글자](/내부주소 또는 https://…)` 둘뿐. 본문에 내부 링크 1개 이상.

## 4. 좋은 글의 기준

- 합니다체, 짧은 문장, 쉬운 말. 전문용어(INV, AWB 같은)는 처음 나올 때 풀어 쓴다.
- 생활정보는 **사례 → 수법 해부 → 구별법 체크리스트(표) → 이미 눌렀다면 할 일(순서) → 신고처(공식 출처)** 흐름이 기본이다.
- 1,500자 아래는 막힌다. 2,000~3,000자가 알맞다. 채우려고 늘리지 않는다.
- 소제목을 질문형으로 쓰면 AI 검색이 잘 가져간다.

## 6. 이 사이트 — 이벤트 코리아 (/column/)

- 이벤트인을 위한 포털: 행사 일감 알림 · 전국 축제 · 입찰 정보 · 이벤트 회사 홈페이지 · 전자명함.
- 읽는 사람: 이벤트 회사 대표 · 실무자, 행사 MC · 스탭 · 공연팀 프리랜서, 축제를 발주하는 지자체 · 기관 담당자.
- 하루: 업계(`industry`) 2개(plan 이 준 주제 · 도시) + 생활정보(`life`) 1개.
- 입찰 · 계약 · 안전 이야기는 조달청 나라장터, 행정안전부, 해당 지자체 공식 누리집에서 **검색으로 확인한 주소**만 출처로 단다.
- 도시 글의 "확인한 사실"은 그 도시의 대표 행사장(공식 누리집) · 대표 축제(공식 누리집 · 한국관광공사) 같은 것. 방문객 수 등 숫자는 출처 없이 쓰지 않는다.
- 이벤트 코리아가 직접 행사를 진행한다고 쓰지 않는다(행사 진행은 자매 회사 큰길이벤트기획). 서비스는 config CTA 에 있는 것만.
